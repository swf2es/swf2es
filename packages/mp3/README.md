# @swf2es/mp3

Synchronous MP3 frame decoding with minimp3, in one WebAssembly module that
imports nothing. Its upstream source is the pinned submodule
[`vendor/minimp3`](../../vendor/minimp3) (https://github.com/swf2es/minimp3,
a fork of lieff/minimp3, at commit `ea99364`), compiled unchanged.

Call `await prepareMp3()` before running scripts. It compiles the embedded
WASM binary once, without instantiating a decoder or decoding any audio.
An `Mp3Decoder` then decodes a sequence of whole frames synchronously.
Its `pcm` view is overwritten by the next `read()`; copy samples out before
reading again. Each decoder owns a fixed 128 KiB workspace and imports
nothing from the host. The module is shared, but decoder state is not.

The player uses this only for `Sound.extract()`. It keeps the samples weakly
by sound, decodes on the first extraction, and preserves Flash's untrimmed
MP3 frame counts. Playback still uses the audio host's decoder.

The package is a Zig project, laid out as `zig init` makes one, inside the
npm package: `build.zig` and `build.zig.zon` at its root, and the Zig
source, `src/root.zig`, beside the TypeScript wrapper (`src/index.ts`) and
the generated `src/binary.ts`. tsc compiles only the `.ts` files, and only
`dist/` and the licence are published, so the Zig source is in the
repository but not in the npm tarball. `include/` holds the two libc
headers minimp3 includes, which wasm32-freestanding lacks; `string.h` maps
`memcpy`, `memmove` and `memset` to clang's builtins, which become bulk
memory instructions.

minimp3 is a single header. `build.zig` translates its declarations for
`src/root.zig` (Zig 0.17 has no `@cImport`) and compiles its implementation
from a generated one-line C file that defines `MINIMP3_IMPLEMENTATION` and
includes it, both with the same defines (`MINIMP3_ONLY_MP3`,
`MINIMP3_NO_SIMD`, `MINIMP3_FLOAT_OUTPUT`), so the sample type cannot
differ between the two. The implementation stays C, compiled by Zig's
clang with `-ffp-contract=off`, rather than translated to Zig, so the
samples are the same arithmetic as before. The target enables wasm SIMD
for what LLVM vectorises on its own, some 12% faster with bit-identical
samples, for 12.7 KB more; minimp3's own SIMD paths are SSE and NEON only
and stay off. Fixed-width SIMD is in every current engine (Chrome 91,
Firefox 89, Safari 16.4, node 16). Where the module does not compile, as
in an engine without it, `prepareMp3()` still resolves, `mp3Available()`
is false, and the player plays on: `Sound.extract()` writes no samples
for an MP3, as Flash does for a sound it cannot decode.

The binary is checked in, so ordinary builds need no compiler. `pnpm build`
verifies its input digest. To rebuild after changing the sources or the
upstream pin:

```sh
pnpm --filter @swf2es/mp3 build:wasm
```

This runs `zig build` here with Zig 0.17.0, from the PATH or else
downloaded once into `~/.cache/swf2es` and checked against its SHA-256,
with fresh caches, and writes the module into `src/binary.ts`. CI rebuilds
and compares the generated bytes. `zig build` alone, in this folder,
builds `zig-out/bin/mp3.wasm` like any Zig project (`.zig-cache/` and
`zig-out/` are ignored). `LICENSE.minimp3` accompanies published builds;
minimp3 is CC0-1.0, and the wrapper and build tools are Apache-2.0.
