# @swf2es/mp3

Synchronous MP3 frame decoding with the upstream C library in
[`vendor/minimp3`](../../vendor/minimp3), pinned as a submodule. The TypeScript
wrapper and C adapter live here; upstream sources stay unchanged.

Call `await prepareMp3()` before running scripts. It compiles the embedded
WASM binary once, without instantiating a decoder or decoding any audio.
An `Mp3Decoder` then decodes a sequence of whole frames synchronously.
Its `pcm` view is overwritten by the next `read()`; copy samples out before
reading again. Each decoder owns a fixed 128 KiB workspace and imports
nothing from the host. The module is shared, but decoder state is not.

The player uses this only for `Sound.extract()`. It keeps the samples weakly
by sound, decodes on the first extraction, and preserves Flash's untrimmed
MP3 frame counts. Playback still uses the audio host's decoder.

The generated binary is checked in as base64 in `src/binary.ts`, so ordinary
builds need no C compiler. `pnpm build` verifies its input digest. To rebuild
after changing the adapter or upstream pin:

```sh
pnpm --filter @swf2es/mp3 build:wasm
```

This runs Clang from the pinned WASI SDK container with Podman or Docker.
CI rebuilds and compares the generated bytes. The adapter needs no WASI
runtime: bulk memory instructions implement its memory copies and fills.
`LICENSE.minimp3` accompanies published builds; the C decoder is CC0-1.0,
and the wrapper and build tools are Apache-2.0.
